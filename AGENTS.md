# AGENTS.md

Guidance for AI agents working in this repo. Read this before touching questions
or the app.

## What this is

A single-file, dark-mode study app for the CompTIA Security+ **SY0-701** exam.
Its one job: kill twin-term confusion (CVE vs CVSS, SPF vs DMARC, hot vs cold
site, and ~100 other sibling sets). No lessons, no navigation tree - adaptive
question modes over one big bank. The whole app ships as a self-contained
`index.html` deployed to GitHub Pages.

There is no framework and no build toolchain (no npm, no bundler). Everything is
vanilla and generated by small Node ESM scripts.

## Repo map

- `index.html` - GENERATED. The deployed app, with all questions + the study
  reference inlined. Never hand-edit; it is overwritten by `build-html.mjs`.
- `data/questions.js` - GENERATED. `export const QUESTIONS = [...]`, the merged
  bank with sequential ids `q001..qNNN`. Never hand-edit.
- `data/gen/chunk*.json` - SOURCE of truth for questions. The originals are
  `chunkA.json`..`chunkI.json`; later expansions add `chunkA2.json`, etc. Edit
  these to change questions.
- `data/families.js` - the family registry: every family's `key`, `domain`
  (D1-D5), `tier` (priority/high/base), and `min` (validator floor).
- `data/generation-guide.md` - the authoring rules AND the per-family sibling
  inventory with canonical "tells". This is also parsed by `build-html.mjs` to
  build the in-app reference sheet, so its `- **family-key**: ... Tell: ...`
  bullet format is load-bearing - keep it.
- `scripts/merge.mjs` - concatenates `data/gen/chunk*.json`, sorts by domain
  then family-registry order, assigns `q001..qNNN`, writes `data/questions.js`.
- `scripts/validate.mjs` - integrity gate (see below). Runs in CI.
- `scripts/build-html.mjs` - inlines questions + reference into `index.html`.
- `SY0-701-objectives.pdf` - the official objectives, the source of truth for
  terminology. When in doubt about a term, it wins.
- `README.md` - user-facing description of the app and modes.

## The pipeline (run in order after any question change)

```
node scripts/merge.mjs        # chunks -> data/questions.js
node scripts/validate.mjs     # must print "OK: all checks passed."
node scripts/build-html.mjs   # data/questions.js + guide -> index.html
```

`validate.mjs` asserts, over the whole bank: ids are sequential and unique; no
duplicate stems (whitespace/case-normalized); exactly 4 unique options with a
valid `correctIndex`; `correctIndex` is reasonably balanced across 0-3; every
family in the registry meets its `min` (priority families >= 8); ZERO banned
terms; every explanation contains the literal `The tell:`; no em/en dashes.

## Question schema (one object per question in a chunk file)

```json
{
  "domain": "D5",
  "family": "agreements",
  "question": "…scenario or definition…",
  "options": ["MOU", "SLA", "NDA", "BPA"],
  "correctIndex": 1,
  "explanation": "SLA. One line of why. The tell: MOU = intent, NDA = confidentiality, BPA = partnership, MSA = master framework."
}
```

Chunk files carry NO `id` field - `merge.mjs` assigns ids by position.

## Non-negotiable content rules

1. **SY0-701 vocabulary only.** These retired SY0-601 terms must appear NOWHERE
   (question, options, or explanation): `DMZ` (use "screened subnet"),
   `man-in-the-middle`/`MITM` (use "on-path"), `white/black/gray box` (use
   "known / partially known / unknown environment"), `whitelist`/`blacklist`
   (use "allow list"/"deny list"), `mantrap` (use "access control vestibule"),
   `whaling`, `pharming`, `tailgating`, `shoulder surfing`, `dumpster diving`,
   `SPIM`.
2. **Acronym disambiguation.** Never a bare `RBAC` option - spell out
   "role-based access control" / "rule-based access control". `MAC` only as
   "mandatory access control". `PAM` = privileged access management only. Do
   not use `SAN` as an option (storage vs subject-alternative-name collision).
3. **Distractors test discrimination, exam-style.** Prefer siblings from the
   family's pool, but plausible cross-category distractors (like the real exam
   uses) are allowed when they make the scenario more realistic - e.g. a
   physical-control question may offer a technical control the reader must
   eliminate. Exactly one defensible answer; if two could be argued, rewrite
   the stem to force one.
4. **Every explanation** starts with the correct term, gives one tight line of
   why, then a sentence beginning literally `The tell:` that discriminates the
   actual siblings shown. Tells must stay consistent with the guide's canonical
   definitions across the whole bank (see coherence, below).
5. **Plain hyphens and colons only. No em or en dashes anywhere.**
6. No duplicate or near-duplicate stems, within or across chunks.

## Adding or expanding questions

- Add new questions in a new chunk file (e.g. `chunkA3.json`) or extend an
  existing one; `merge.mjs` picks up any `data/gen/chunk*.json`. New chunks sort
  after the originals, so existing questions keep their relative order.
- When generating in bulk, feed each writer the EXISTING stems for its families
  so it cannot duplicate them, then re-run the pipeline. The validator catches
  exact-dup stems; also run a family-scoped Jaccard scan for near-dups.
- Positional ids mean adding questions shifts `q0NN` numbers. Per-question
  localStorage stats are keyed by id, so a large insert can misalign a user's
  saved per-question progress (per-family stats and exam history are keyed by
  name/are unaffected). Acceptable, but worth noting in the change.
- If you add a brand-new family, add it to `data/families.js` (with a `min`) AND
  add its `- **key**: siblings. Tell: …` bullet to the generation guide, or the
  reference sheet and validator coverage check will complain.

## Coherence

A term is discriminated in many explanations across families. Its definition/
tell must agree everywhere (e.g. "risk tolerance" must mean the same thing in
cve-cvss and risk-appetite questions; site recovery times must be consistent).
After large edits, sweep for contradictory "X = …" tell phrasings and reconcile
against the guide.

## The app (index.html via build-html.mjs)

Vanilla HTML/CSS/JS, mobile-first (max ~520px card), dark mode only. Palette and
behavior live entirely in `build-html.mjs`'s template string. Modes:

- **Practice exam** - 90 questions / 90 min, official domain weights
  (D1 11, D2 20, D3 16, D4 25, D5 18), adaptive selection within each domain
  quota, scaled 100-900 score vs 750, per-domain report. Only these enter the
  saved exam-score history.
- **Custom quiz** - user picks question count + time limit (0 = untimed) via
  sliders; adaptive fill; percent score; kept out of exam history.
- **Smart drill** - 25 adaptive questions. **Full stream** - all shuffled.
- **Feedback setting** (home toggle, persisted): Instant (grade on tap; the
  exam adds a "Lock in answer" confirm step) or At-the-end (deferred, with
  flag + question grid for exams).
- Every result screen offers **Review all** and **Review missed**.

**Adaptive engine** (`weightFor`/`adaptivePick`): weights missed-last-time (4x)
> unseen (3x) > shaky (2x) > solid (1x) > mastered (0.4x), multiplied for weak
families (<80% accuracy), damped for recently-seen; a family-spread factor stops
one family hogging a quota. Exam and quiz answers feed the same stats the drill
reads.

**localStorage** key `secplus-drill-stats-v1` (schema v2 with v1 migration):
`{v, seq, perQuestion:{id:{a,c,s,last}}, perFamily:{key:{a,c}}, exams:[], pref}`.
`s` is the correct-streak, `last` is the seq of last exposure. Bump the version
and migrate if you change the shape.

## Deploy

`.github/workflows/deploy.yml` runs on push to `main`: it runs
`node scripts/validate.mjs`, then publishes `index.html` to GitHub Pages
(branch `gh-pages`). There is no `npm ci`/build step - do not reintroduce one.

Workflow for changes: develop on the working branch, run the full pipeline
locally, verify the app in a headless browser, commit, then merge to `main` to
deploy. Keep `index.html`, `data/questions.js`, and the chunk sources in sync in
the same commit (regenerate, don't hand-edit the generated files).
