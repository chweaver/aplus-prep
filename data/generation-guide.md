# SY0-701 Twin-Term Drill: Question Generation Guide

You are writing multiple-choice questions for a CompTIA Security+ **SY0-701 V7** drill
whose ONLY purpose is to kill twin-term confusion. Every question pits sibling terms
from the same confusion family against each other. Follow this guide exactly.

## Output contract

Return ONLY a JSON array (a fenced ```json block, nothing else). Each element:

```json
{
  "domain": "D5",
  "family": "agreements",
  "question": "A company signs an agreement with its MSP guaranteeing 99.9% uptime and four-hour response times, with financial penalties for missing targets. Which agreement type is this?",
  "options": ["MOU", "SLA", "NDA", "BPA"],
  "correctIndex": 1,
  "explanation": "SLA. Numbers plus penalties equals SLA. The tell: MOU = non-binding intent, NDA = confidentiality only, BPA = partnership terms, MSA = master framework that SOWs hang off of."
}
```

Do NOT include an `id` field (ids are assigned later). Use the exact `family` key and
`domain` you are told to produce. Produce the EXACT count requested per family.

## Hard rules (a validator enforces these; violations get the whole batch rejected)

1. **Exactly 4 options. Exactly one defensible correct answer.** If two options could
   both be argued correct, rewrite the stem until only one survives.
2. **Distractors should test discrimination.** Draw primarily from the family's
   sibling pool (see inventory below), but exam-style cross-category distractors
   are allowed when they make the scenario more realistic (the real SY0-701 mixes
   option categories and asks for the BEST answer). Never pad with implausible
   throwaway options; every distractor must be tempting to someone who half-knows
   the material.
3. **Explanation format**: correct term first, then one short line of why, then a
   sentence that begins literally with `The tell:` giving a one-phrase discriminator
   for each relevant sibling. The `The tell:` substring is mandatory in every explanation.
4. **Stem styles**, mix across your batch roughly 70/20/10 (the real exam is
   almost entirely scenario-based):
   - (a) realistic workplace scenario with a role, a situation, and a qualifier
     like "BEST", "MOST appropriate", or "FIRST" -> pick the term (~70%)
   - (b) definition/behavior -> pick the term (~20%)
   - (c) term given -> pick the correct behavior/definition (~10%)
   Scenario stems should read like the exam: a named role (security analyst,
   administrator, technician), a concrete situation with specifics (systems,
   numbers, constraints), then the ask.
5. **Rotate the correct sibling** within each family so the answer is not always the
   same term. **Vary `correctIndex`** so across the whole batch each of 0,1,2,3 is used
   a healthy share (aim 20-30% each). Do not park the answer at one index.
6. **No duplicate or near-duplicate stems.** Same family, different angle every time.
7. **Plain hyphens and colons only. NO em dashes or en dashes anywhere** (no `—`, `–`).
   Use " - " or ": " or ". " instead.
8. Keep stems tight and realistic. Numbers, roles, and scenarios should feel like the
   real exam. No trick wording; the difficulty is term discrimination, not reading.

## BANNED terms (SY0-601 leftovers). Must appear NOWHERE in question, options, or explanation:

- `DMZ` (701 says "screened subnet")
- `man-in-the-middle` / `MITM` (701 says "on-path")
- `white box` / `black box` / `gray box` / `grey box` (701 says "known / partially known / unknown environment")
- `whitelist` / `blacklist` (701 says "allow list / deny list")
- `mantrap` (701 says "access control vestibule")
- `whaling`, `pharming`, `tailgating`, `shoulder surfing`, `dumpster diving`, `SPIM`

## Acronym disambiguation (mandatory):

- Never use bare `RBAC` as an option. Write "role-based access control" or
  "rule-based access control" in full.
- `MAC` only ever means "mandatory access control" here; spell it out
  ("mandatory access control") to avoid media-access-control / message-auth-code collisions.
- `PAM` = privileged access management only.
- Do NOT use `SAN` as an option (storage area network vs subject alternative name collision).
  If you need subject alternative name, write it out; prefer other siblings.

# Family -> confusion-set inventory

For each family: the sibling pool your options must be drawn from, plus the discriminators
(the "tells") to embed in explanations. Draw all 4 options from the listed siblings for
that family. You do not have to use every sibling in one question; rotate them.

## Domain 1 - General Security Concepts

- **control-categories**: technical / managerial / operational / physical. Tell: technical = implemented in tech/hardware/software (firewall, encryption); managerial = administrative decisions/policy/risk (security policy, risk assessments); operational = day-to-day human processes (guard rotations, awareness training, incident handling); physical = tangible barriers (locks, fences, guards).
- **control-types**: preventive / deterrent / detective / corrective / compensating / directive. Tell: preventive = stops it before (lock, ACL); deterrent = discourages (warning sign, lighting); detective = finds it after (IDS, logs, cameras reviewing); corrective = fixes/restores after (backup restore, patch); compensating = alternate when primary is not feasible (extra monitoring when you cannot patch); directive = mandates behavior (policy, acceptable use).
- **cia-nonrepudiation**: confidentiality / integrity / availability / non-repudiation. Tell: confidentiality = secrecy (encryption); integrity = unaltered (hashing, checksums); availability = uptime (redundancy, backups); non-repudiation = cannot deny you did it (digital signatures, audit logs).
- **aaa**: authentication / authorization / accounting. Tell: authentication = prove who you are; authorization = what you are allowed to do; accounting = recording what you did (logs, session records).
- **zero-trust**: Policy Engine / Policy Administrator / Policy Enforcement Point; control plane vs data plane; adaptive identity / threat scope reduction / policy-driven access control / implicit trust zones. Tell: Policy Engine = makes the grant/deny decision; Policy Administrator = generates/relays the access token to the PEP; Policy Enforcement Point = the gate that actually allows/blocks the session; control plane = where policy decisions live; data plane = where the traffic/subject actually flows.
- **physical-security**: bollards / fencing / access control vestibule / video surveillance / security guard / access badge / lighting / sensors (infrared, pressure, microwave, ultrasonic). Tell: bollards = stop vehicles; access control vestibule = one-person-at-a-time double-door to stop piggybacking; infrared sensor = detects heat/body; pressure sensor = detects weight/step; microwave/ultrasonic = detect motion via reflected waves.
- **deception**: honeypot / honeynet / honeyfile / honeytoken. Tell: honeypot = one decoy system; honeynet = a whole decoy network; honeyfile = a bait file; honeytoken = a bait credential/record that fires an alert when used.
- **change-management**: approval process / ownership / stakeholders / impact analysis / test results / backout plan / maintenance window / standard operating procedure (SOP); allow list vs deny list; version control. Tell: impact analysis = what could break; backout plan = how to undo; maintenance window = approved time to make the change; SOP = the repeatable documented procedure; version control = track revisions of code/config.
- **crypto-key-handling** (PRIORITY): TPM / HSM / secure enclave / key management system / key escrow. Tell: TPM = crypto chip built into ONE endpoint's motherboard (boot integrity, disk key); HSM = dedicated hardware appliance that generates/stores keys at scale for many systems; secure enclave = isolated coprocessor region on a CPU/phone for keys/biometrics; key management system = software service that handles key lifecycle (create/rotate/revoke); key escrow = a third party holds a copy of keys for recovery/legal access. Hit "key escrow vs HSM" and "TPM vs HSM" hard.
- **crypto-methods**: symmetric vs asymmetric; key exchange; key stretching; salting; hashing. Tell: symmetric = one shared key, fast, bulk data; asymmetric = public/private key pair, slower, key exchange and signatures; key exchange = safely agree on a shared key (Diffie-Hellman); key stretching = make a weak password expensive to brute force (PBKDF2, bcrypt); salting = add random per-password value to defeat rainbow tables; hashing = one-way integrity fingerprint.
- **pki-signatures**: public key vs private key roles; digital signature; hashing; blockchain; open public ledger. Tell: encrypt for confidentiality = recipient's PUBLIC key (only their private key opens it); sign for non-repudiation = sender's PRIVATE key (anyone verifies with the public key); digital signature = hash of message encrypted with signer's private key (integrity + non-repudiation); blockchain = chained hashed blocks; open public ledger = the publicly visible record of blockchain transactions.
- **obfuscation**: steganography / tokenization / data masking. Tell: steganography = hide data inside other media (image, audio); tokenization = replace sensitive value with a token that maps back via a vault; data masking = show partial/scrambled value (XXXX-1234) that cannot be reversed.
- **encryption-levels**: full-disk / partition / volume / file / database / record. Tell: full-disk = the entire drive; partition = one partition; volume = a logical volume; file = individual files; database = the whole database; record = a single row/field inside the database.
- **certificates**: CRL vs OCSP; self-signed vs third-party; wildcard; CSR; root of trust; certificate authority. Tell: CRL = a downloaded list of revoked certs (batch, can be stale); OCSP = real-time single-cert revocation check; self-signed = you signed it yourself, no external trust; third-party/CA-issued = a trusted CA vouches for it; wildcard = covers *.domain subdomains; CSR = the request you send to a CA to get a cert; root of trust = the anchor CA the chain terminates at.

## Domain 2 - Threats, Vulnerabilities, Mitigations

- **threat-actors**: nation-state / organized crime / hacktivist / insider threat / unskilled attacker / shadow IT; motivations: espionage / data exfiltration / blackmail / financial gain / philosophical-political / ethical / revenge / disruption / war. Tell: nation-state = highly resourced, espionage/war, APT; organized crime = financial gain; hacktivist = philosophical/political message; insider threat = trusted internal person; unskilled attacker = uses others' tools (script), low skill; shadow IT = unsanctioned internal tech, not malicious intent.
- **social-eng-phish**: phishing / vishing / smishing. Tell: phishing = email; vishing = voice call; smishing = SMS text.
- **misinformation** (HIGH): misinformation vs disinformation. Tell: misinformation = false info spread WITHOUT intent to deceive (honest mistake); disinformation = false info spread deliberately to deceive/manipulate.
- **impersonation**: impersonation / brand impersonation / pretexting / business email compromise (BEC). Tell: impersonation = pretend to be someone (help desk); brand impersonation = fake a trusted company's look; pretexting = invent a believable backstory to justify the ask; BEC = compromised/spoofed internal executive email requesting wire/gift cards.
- **social-eng-other**: watering hole / typosquatting. Tell: watering hole = compromise a site the target group already visits; typosquatting = register a misspelled lookalike domain.
- **attack-vectors**: message-based (email/SMS/IM) / image-based / file-based / voice call / removable device / client-based vs agentless / open service ports / default credentials / unsecure networks. Tell: client-based = requires installed agent that can be compromised; agentless = no installed software (less footprint, less control); removable device = USB vector; open service ports = exposed listening service; default credentials = unchanged out-of-box password.
- **supply-chain**: managed service provider (MSP) / vendor / supplier; service provider / hardware provider / software provider. Tell: MSP = third party that runs your IT operations; vendor = sells you a product/service; supplier = provides parts/materials upstream; hardware provider = supplies devices; software provider = supplies applications.
- **app-vulns**: memory injection / buffer overflow / SQL injection (SQLi) / cross-site scripting (XSS) / malicious update. Tell: memory injection = insert code into a running process's memory; buffer overflow = write past a buffer boundary to overwrite memory; SQLi = inject SQL into a query to hit the database; XSS = inject script that runs in another user's browser; malicious update = trojanized software update.
- **race-conditions** (HIGH): time-of-check (TOC) vs time-of-use (TOU). Tell: race condition = outcome depends on timing of events; TOC = the moment a resource/permission is checked; TOU = the moment it is actually used; the gap between check and use is the exploit window (TOCTOU).
- **system-vulns**: firmware / end-of-life / legacy / VM escape / resource reuse / side loading / jailbreaking / misconfiguration / zero-day. Tell: end-of-life = vendor stopped selling/supporting; legacy = outdated but still running; VM escape = break out of a guest to the hypervisor/host; resource reuse = leftover data in reallocated memory/storage; side loading = install apps outside the official store; jailbreaking = remove OS restrictions for root; zero-day = no patch exists yet.
- **malware** (HIGH): virus / worm / trojan / ransomware / spyware / bloatware / keylogger / logic bomb / rootkit. Tell: virus = needs a host file and user action to spread; worm = self-replicates across the network with no user action; trojan = disguised as legitimate; ransomware = encrypts and extorts; spyware = secretly collects activity; bloatware = unwanted preinstalled software; keylogger = records keystrokes; logic bomb = payload triggered by a condition/date; rootkit = hides at OS/kernel level to keep persistence.
- **ddos-network** (HIGH): DDoS amplified vs reflected; DNS attacks / on-path / credential replay / wireless. Tell: amplified = small request yields a huge response aimed at the victim; reflected = spoof the victim's source so third parties reply to the victim; on-path = attacker sits between two parties to read/alter traffic; credential replay = capture and resend valid credentials/session; DNS attack = poison/hijack name resolution.
- **app-attacks**: injection / replay / privilege escalation / forgery (request forgery) / directory traversal. Tell: injection = insert malicious input into an interpreter; replay = resend captured valid traffic; privilege escalation = gain higher rights than granted; forgery = trick a user/site into sending a state-changing request (CSRF); directory traversal = ../ path tricks to read files outside web root.
- **crypto-attacks** (HIGH): downgrade / collision / birthday. Tell: downgrade = force a weaker protocol/cipher (TLS to SSL); collision = two different inputs produce the same hash; birthday = probability attack that finds collisions faster than expected (birthday paradox).
- **password-attacks** (HIGH): spraying vs brute force (and dictionary). Tell: spraying = a few common passwords tried against MANY accounts to avoid lockout; brute force = exhaustively try many passwords against ONE account; dictionary = try a wordlist of likely passwords.
- **indicators** (HIGH): account lockout / concurrent session usage / impossible travel / blocked content / resource consumption / resource inaccessibility / out-of-cycle logging / missing logs / published-documented. Tell: impossible travel = logins from distant places too close in time; concurrent session usage = same account active in multiple sessions at once; out-of-cycle logging = log entries at unusual times; missing logs = gaps suggest tampering; resource inaccessibility = services suddenly unavailable (possible ransomware/DoS).
- **mitigations**: segmentation / isolation / ACL / permissions / application allow list / least privilege / configuration enforcement / decommissioning / patching / hardening (host-based firewall, HIPS, disable ports/protocols, default password changes, remove unnecessary software, endpoint protection). Tell: segmentation = split the network into zones; isolation = fully cut a host off; least privilege = minimum rights needed; application allow list = only approved apps run; configuration enforcement = push and hold a secure config; decommissioning = securely retire an asset.

## Domain 3 - Security Architecture

- **containerization** (HIGH): containerization vs virtualization; IaC / serverless / microservices. Tell: virtualization = full guest OS per VM on a hypervisor; containerization = share the host kernel, package app + deps only (lighter); serverless = provider runs functions, no server to manage; microservices = app split into small independent services; IaC = provision infrastructure from code/templates.
- **isolation-models**: air-gapped (physical isolation) / logical segmentation / SDN; centralized vs decentralized; on-premises vs cloud. Tell: air-gapped = physically no network connection; logical segmentation = VLANs/subnets separate traffic on shared hardware; SDN = software-controlled network via control/data plane split; centralized = one control point; decentralized = distributed control.
- **embedded-systems**: IoT / ICS / SCADA / RTOS / embedded systems. Tell: IoT = internet-connected consumer/smart devices; ICS = industrial control systems running physical processes; SCADA = the supervisory layer that monitors/controls ICS over wide areas; RTOS = OS with guaranteed timing for real-time tasks; embedded = special-purpose computer inside a larger device.
- **arch-considerations**: availability / resilience / responsiveness / scalability / ease of deployment / ease of recovery / patch availability / inability to patch / risk transference / cost / power / compute. Tell: availability = uptime now; resilience = recover and keep serving under failure; scalability = grow to handle more load; responsiveness = latency of the response; risk transference = shift risk to a third party (insurance/vendor).
- **fail-modes** (HIGH): fail-open vs fail-closed (network devices); fail-safe vs fail-secure (physical locks). Tell: fail-open = on failure the network device PERMITS traffic (favors availability); fail-closed = on failure it BLOCKS traffic (favors security); fail-safe = on failure the door UNLOCKS to protect people (life safety); fail-secure = on failure the door STAYS LOCKED to protect assets. Network pair = open/closed; door-lock pair = safe/secure.
- **active-passive** (HIGH): active vs passive; inline vs tap/monitor. Tell: active device = sits in the traffic path and can block (inline, like IPS); passive device = only observes a copy and cannot block (tap/monitor, like IDS on a SPAN port); inline = traffic flows through it; tap/monitor = gets a mirrored copy.
- **jump-proxy** (HIGH): jump server vs proxy server. Tell: jump server = a hardened admin gateway host you connect THROUGH to manage internal systems; proxy server = an intermediary that forwards/filters client requests to services (often web). Jump = admin access pivot; proxy = request broker/filter.
- **ips-ids** (HIGH): IPS vs IDS. Tell: IDS = detects and alerts only, passive, out of band; IPS = detects AND blocks, active, inline. Same detection, different response and placement.
- **firewalls**: WAF / UTM / NGFW / Layer 4 vs Layer 7. Tell: WAF = protects web apps from injection/XSS at Layer 7; UTM = all-in-one appliance (firewall + AV + IDS + filter); NGFW = firewall with app awareness, deep inspection, identity; Layer 4 = filters by port/IP; Layer 7 = filters by application content.
- **port-auth**: 802.1X / EAP. Tell: 802.1X = port-based network access control that requires authentication before the port opens; EAP = the authentication framework 802.1X carries (PEAP, EAP-TLS are EAP methods). 802.1X = the gate; EAP = the language spoken through it.
- **secure-tunnels** (HIGH): TLS vs IPSec tunneling; SD-WAN vs SASE; VPN. Tell: TLS VPN = tunnel at the transport/application layer, clientless-friendly, port 443; IPSec = tunnel at the network layer (AH/ESP), site-to-site; SD-WAN = software-defined WAN that optimizes links between sites; SASE = SD-WAN plus cloud-delivered security (ZTNA, SWG, CASB) as one service.
- **data-classification**: data types (regulated / trade secret / intellectual property / legal / financial) and classifications (sensitive / confidential / public / restricted / private / critical). Tell: regulated = governed by law/standard (PCI, HIPAA); trade secret = proprietary competitive info; intellectual property = patents/copyrights; public = no harm if released; confidential/restricted = harm if released; critical = essential to operations.
- **data-states**: at rest / in transit / in use; data sovereignty / geolocation. Tell: at rest = stored (disk encryption); in transit = moving over a network (TLS); in use = actively processed in memory (hardest to protect); data sovereignty = data is subject to the laws of the country it physically sits in.
- **data-protection**: encryption / hashing / masking / tokenization / obfuscation / segmentation / permission restrictions / geographic restrictions. Tell: encryption = reversible with a key (confidentiality); hashing = one-way (integrity); masking = show partial value; tokenization = swap for a vaulted token; geographic restrictions = allow/deny by location; permission restrictions = control by access rights.
- **load-balancing** (HIGH): load balancing vs clustering. Tell: load balancing = distribute incoming requests across multiple active servers for throughput; clustering = multiple nodes act as one system with failover so if one dies another takes over. Load balancer = spread traffic; cluster = high-availability failover group.
- **sites** (PRIORITY): hot / warm / cold / geographic dispersion. Tell: hot site = fully equipped and running, near-instant failover (minutes); warm site = hardware and connectivity ready but data must be loaded (hours); cold site = just space and power, everything must be brought in (days/weeks); geographic dispersion = keep sites far enough apart that one disaster cannot hit both. Drill "cold vs hot" and "warm vs cold" hard.
- **resilience-planning**: platform diversity / multi-cloud / continuity of operations (COOP) / capacity planning (people, technology, infrastructure). Tell: platform diversity = use different vendors/OSes so one flaw does not sink all; multi-cloud = spread across cloud providers; COOP = plan to keep essential functions running; capacity planning = size people/tech/infra for demand.
- **continuity-testing** (HIGH): tabletop / failover / simulation / parallel processing. Tell: tabletop = discussion-based walkthrough, no systems touched; failover test = actually cut over to the backup system; simulation = act out a scenario with real steps but controlled; parallel processing = run the recovery site alongside production to compare without taking prod down.
- **backups** (PRIORITY): snapshots / replication / journaling / frequency / onsite vs offsite / encryption / recovery. Tell: snapshot = point-in-time image of a system/volume you can roll back to; replication = continuously copy data to another location in near real time; journaling = log every change so you can replay transactions to a precise point; onsite = fast restore but shares the disaster; offsite = survives a site loss but slower. Drill "snapshots vs journaling" and "replication vs snapshots" hard.
- **power**: generators vs UPS. Tell: UPS = battery for instant, short-term ride-through (seconds to minutes, no gap); generator = fuel-powered long-term supply that takes seconds to start. UPS bridges until the generator comes online.

## Domain 4 - Security Operations

- **baselines**: establish / deploy / maintain. Tell: establish = define the secure baseline config; deploy = push it to systems; maintain = keep it enforced and updated over time.
- **wireless-install**: site survey / heat map; WPA3 / RADIUS; cryptographic vs authentication protocols. Tell: site survey = walk the space to plan AP placement/coverage; heat map = visual signal-strength map output; WPA3 = the encryption standard; RADIUS = centralized AAA server for enterprise Wi-Fi auth.
- **mobile-deployment** (HIGH): BYOD / COPE / CYOD; MDM. Tell: BYOD = employee-owned device (least company control); COPE = company-owned, personally enabled (company owns, personal use allowed); CYOD = choose from a company-approved list, company-owned; MDM = the tool that enforces policy on all of them.
- **app-security**: input validation / secure cookies / static code analysis / code signing / sandboxing / monitoring. Tell: input validation = reject bad input to stop injection; secure cookies = flags so cookies are not stolen/sent in clear; static analysis = review code without running it; code signing = sign the binary so users verify integrity/origin; sandboxing = run untrusted code in isolation.
- **asset-management**: inventory / enumeration; acquisition/procurement / assignment/accounting / ownership / classification. Tell: inventory = the list of assets you own; enumeration = actively discovering assets on the network; acquisition = procuring the asset; assignment = accounting for who owns/uses it.
- **asset-disposal** (HIGH): sanitization / destruction / certification / data retention. Tell: sanitization = wipe data so the media can be reused; destruction = physically shred/degauss so media is gone; certification = documented proof the data was destroyed; data retention = how long you must keep data before disposal.
- **analysis-types** (HIGH): static analysis vs dynamic analysis; package monitoring. Tell: static analysis = examine code/binary WITHOUT executing it; dynamic analysis = run it and watch behavior (sandbox, fuzzing); package monitoring = watch third-party dependencies for known vulns.
- **threat-intel**: OSINT / proprietary-third-party / information-sharing organization / dark web. Tell: OSINT = free public sources; proprietary/third-party = paid vendor feeds; information-sharing organization = ISAC/community sharing (industry peers); dark web = monitoring criminal marketplaces/forums.
- **security-assessments**: penetration testing / bug bounty (responsible disclosure) / system-process audit. Tell: penetration testing = authorized simulated attack by a team; bug bounty = pay external researchers per valid finding (responsible disclosure); system/process audit = check controls and procedures against requirements.
- **false-pos-neg** (HIGH): false positive vs false negative. Tell: false positive = alert fired but nothing was actually wrong (wastes time); false negative = real threat that was NOT detected (dangerous miss). Positive = it alerted; negative = it stayed silent.
- **cve-cvss** (PRIORITY): CVE vs CVSS; exposure factor / environmental variables / risk tolerance / vulnerability classification. Tell: CVE = the unique ID/name for a specific known vulnerability (a catalog entry); CVSS = the 0-10 numeric SEVERITY score for a vulnerability; exposure factor = percent of an asset lost in an event; environmental variables = CVSS modifiers for YOUR specific environment; vulnerability classification = grouping by type/severity. Drill "CVE (identifier) vs CVSS (score)" hard.
- **vuln-response**: patching / insurance / segmentation / compensating controls / exceptions and exemptions; validation: rescanning / audit / verification. Tell: patching = fix the flaw; insurance = transfer the financial risk; compensating control = alternate protection when you cannot fix; exception/exemption = formally accept and document leaving it unfixed; rescanning = confirm the fix by scanning again.
- **monitoring**: log aggregation / alerting / archiving / scanning / reporting; quarantine / alert tuning. Tell: log aggregation = collect logs into one place; alerting = notify on conditions; archiving = retain logs long-term; quarantine = isolate a suspicious file/host; alert tuning = adjust rules to cut false positives.
- **security-tools** (HIGH): SIEM / DLP / SNMP traps / NetFlow / vulnerability scanner / antivirus / SCAP / benchmarks / agents vs agentless. Tell: SIEM = correlate logs and alert across the enterprise; DLP = stop sensitive data from leaving; SNMP traps = device-initiated alerts to a manager; NetFlow = records of traffic flows (who talked to who, volume); vulnerability scanner = finds known weaknesses; SCAP = standard that lets tools automate/compare security config checks.
- **firewall-config**: firewall rules / access lists / ports and protocols / screened subnets; IDS-IPS trends and signatures. Tell: rule/ACL = permit or deny by source/dest/port; screened subnet = a buffer network between the internet and the internal LAN for public-facing servers; signature = match a known pattern; trend = detect deviation over time.
- **web-filter**: agent-based / centralized proxy / URL scanning / content categorization / block rules / reputation; DNS filtering. Tell: agent-based = client software enforces filtering anywhere; centralized proxy = all traffic routed through one filtering point; content categorization = block by category (gambling, adult); reputation = block by known-bad score; DNS filtering = block by refusing to resolve bad domains.
- **os-hardening** (HIGH): Group Policy vs SELinux. Tell: Group Policy = Windows centralized config/enforcement via Active Directory (GPOs); SELinux = Linux mandatory access control that confines processes with security contexts. Group Policy = Windows domain config; SELinux = Linux MAC enforcement.
- **email-security** (PRIORITY): SPF / DKIM / DMARC / gateway. Tell: SPF = lists which mail servers are ALLOWED to send for the domain (checks the sending IP); DKIM = cryptographic SIGNATURE proving the message was not altered and came from the domain; DMARC = the POLICY built on SPF+DKIM that tells receivers what to do on failure (none/quarantine/reject) and where to send reports (alignment); secure email gateway = the appliance that filters inbound/outbound mail. Drill "SPF vs DMARC" and "DKIM vs DMARC" hard.
- **endpoint-detection** (HIGH): file integrity monitoring (FIM) / DLP / NAC / EDR / XDR / UBA (user behavior analytics). Tell: FIM = alert when critical files change; DLP = block sensitive data exfiltration; NAC = check device posture before allowing it on the network; EDR = detect/respond on endpoints; XDR = correlate detection across endpoints, network, cloud, email; UBA = flag abnormal user behavior.
- **identity-lifecycle**: provisioning / de-provisioning; identity proofing / attestation; federation / single sign-on (SSO). Tell: provisioning = create the account/access; de-provisioning = remove access at offboarding; identity proofing = verify who a person is before issuing identity; attestation = periodic review confirming access is still appropriate; federation = trust identities across organizations; SSO = one login for many apps.
- **federation-protocols** (HIGH): LDAP / OAuth / SAML. Tell: LDAP = directory query protocol to look up users/groups (on-prem AD); SAML = XML-based browser SSO for enterprise web apps (assertions between IdP and SP); OAuth = authorization/delegated access via tokens (let an app act on your behalf, often with OIDC for auth). SAML = enterprise web SSO; OAuth = API/app authorization; LDAP = directory lookup.
- **access-control-models** (HIGH): mandatory access control / discretionary access control / role-based access control / rule-based access control / attribute-based access control; time-of-day restrictions / least privilege. Tell: mandatory access control = labels/clearances set by the system, users cannot change (military); discretionary access control = the data OWNER grants access; role-based access control = access by job role/group; rule-based access control = access by system-wide if/then rules (time, ACL condition); attribute-based access control = access by evaluated attributes (department + location + device).
- **mfa**: factors - something you know / have / are / somewhere you are; biometrics / hard tokens / soft tokens / security keys. Tell: know = password/PIN; have = token/phone/security key; are = biometric (fingerprint); somewhere you are = geolocation; hard token = physical device generating codes; soft token = app-generated code; two of the SAME factor is not MFA.
- **password-security**: length / complexity / reuse / expiration / age; password managers / passwordless. Tell: length = number of characters (biggest strength driver); complexity = character variety; reuse = using the same password across accounts (bad); expiration = forced change interval; age = minimum time before you can change again; passwordless = authenticate without a password (biometric, key).
- **pam** (HIGH): just-in-time permissions / password vaulting / ephemeral credentials. Tell: just-in-time = grant elevated rights only for the moment needed then revoke; password vaulting = store/check-out privileged passwords from a secured vault; ephemeral credentials = short-lived credentials that self-expire after use.
- **automation**: user vs resource provisioning / guard rails / security groups / ticket creation / escalation / continuous integration / APIs; benefits vs complexity / cost / single point of failure / technical debt / supportability. Tell: guard rails = automated limits that keep actions within policy; ticket creation = auto-open a tracked work item; escalation = auto-route to a higher tier; single point of failure = the automation itself becoming a critical dependency.
- **ir-process** (HIGH): preparation -> detection -> analysis -> containment -> eradication -> recovery -> lessons learned. Tell (ORDER matters): preparation = before anything (plans, tools); detection = notice the event; analysis = confirm and scope it; containment = stop the spread; eradication = remove the threat/artifacts; recovery = restore to normal operations; lessons learned = post-incident review to improve. Write "what phase comes next / what phase is this" questions.
- **ir-testing**: tabletop / simulation; root cause analysis / threat hunting. Tell: tabletop = talk through the plan; simulation = act it out; root cause analysis = find the underlying cause after an incident; threat hunting = proactively search for threats that evaded detection.
- **forensics** (HIGH): legal hold / chain of custody / acquisition / preservation / reporting / e-discovery. Tell: legal hold = preserve data because litigation is anticipated; chain of custody = documented who handled evidence and when; acquisition = collect/image the evidence; preservation = protect it from alteration; e-discovery = locate and produce electronic evidence for legal process.
- **log-sources**: firewall / application / endpoint / OS-specific / IPS-IDS / network / metadata; vulnerability scans / automated reports / dashboards / packet captures. Tell: firewall log = allow/deny by connection; endpoint log = activity on a host; OS security log = auth/audit events; network log = flow/traffic; metadata = data about the data (headers, timestamps); packet capture = full raw traffic content.

## Domain 5 - Program Management and Oversight

- **governance-hierarchy** (HIGH): guidelines / policies / standards / procedures. Tell: policy = high-level mandatory statement of intent (the "what/why"); standard = mandatory specific requirement that supports a policy (the "how much", e.g. AES-256); procedure = step-by-step instructions (the "how"); guideline = recommended, non-mandatory best practice.
- **policies** (HIGH): AUP / information security / business continuity (BC) / disaster recovery (DR) / incident response / SDLC / change management. Tell: AUP = rules for acceptable use of systems; business continuity = keep the BUSINESS operating during disruption (broad, proactive); disaster recovery = restore IT SYSTEMS after a disaster (technical subset, reactive); incident response = handle security incidents; SDLC = secure software development process. Drill "BC (keep business running) vs DR (restore IT)" hard.
- **standards-procedures**: standards (password / access control / physical security / encryption); procedures (change management / onboarding-offboarding / playbooks). Tell: standard = the required spec; playbook = the procedure for a specific scenario; onboarding = grant access for a new hire; offboarding = revoke access at exit.
- **external-governance**: regulatory / legal / industry / local-regional / national / global. Tell: regulatory = government rules with enforcement; legal = laws/contracts; industry = sector frameworks (PCI DSS); local/national/global = jurisdiction scope.
- **data-roles** (HIGH): owner / controller / processor / custodian-steward. Tell: data owner = accountable senior person who sets classification and rules; data controller = decides WHY and HOW data is processed (GDPR); data processor = processes data ON BEHALF of the controller (a vendor); data custodian/steward = hands-on technical care and day-to-day protection. Drill "controller (decides) vs processor (acts for controller)" hard.
- **risk-assessment-types**: ad hoc / recurring / one-time / continuous. Tell: ad hoc = as-needed, triggered by an event; recurring = on a fixed schedule; one-time = single point assessment; continuous = ongoing automated monitoring.
- **qual-quant** (HIGH): qualitative vs quantitative. Tell: qualitative = subjective ratings (high/medium/low, likelihood-impact matrix); quantitative = objective dollar figures and math (SLE, ALE, ARO). Qualitative = judgment/labels; quantitative = numbers/money.
- **risk-math** (HIGH): SLE / ALE / ARO / exposure factor / asset value. Formulas: SLE = Asset Value x Exposure Factor; ALE = SLE x ARO; ARO = expected occurrences per year. Tell: SLE = loss from ONE event; ARO = how many times per year (once every 4 years = 0.25); ALE = expected yearly loss = SLE x ARO; exposure factor = percent of asset value lost per event. Include real numbers; use "once every N years" ARO traps (ARO = 1/N). Vary the numbers each question.
- **probability-impact**: probability / likelihood / exposure factor / impact. Tell: probability = statistical chance; likelihood = qualitative chance rating; impact = magnitude of harm if it happens; exposure factor = percent of asset lost.
- **risk-register**: key risk indicators (KRIs) / risk owners / risk threshold. Tell: KRI = a metric that warns risk is rising; risk owner = the person accountable for managing that risk; risk threshold = the level at which action is required.
- **risk-appetite** (HIGH): risk tolerance / risk appetite (expansionary / conservative / neutral). Tell: risk appetite = the broad amount of risk an org is WILLING to pursue for reward (expansionary = high appetite, conservative = low, neutral = balanced); risk tolerance = the acceptable VARIANCE around a specific risk before acting. Appetite = overall willingness; tolerance = how much deviation is acceptable.
- **risk-strategies** (PRIORITY): transfer / accept / avoid / mitigate; exemption vs exception. Tell: transfer = shift the risk to another party (insurance, outsource); accept = knowingly take no action and live with it; avoid = stop the activity entirely so the risk is gone; mitigate = reduce the risk with controls; exemption = pre-approved standing pass from a requirement; exception = a one-off approved deviation. Drill "accept (live with it) vs transfer (insure/outsource) vs avoid (stop doing it)" hard.
- **bia** (HIGH): RTO / RPO / MTTR / MTBF. Tell: RTO = how fast you must RESTORE service (time target forward from outage); RPO = how much DATA loss is acceptable (time backward to last good backup); MTTR = mean time to repair (avg fix time); MTBF = mean time between failures (avg uptime between breakdowns). Drill "RTO (restore time) vs RPO (data-loss point)" hard.
- **vendor-assessment**: penetration testing / right-to-audit clause / evidence of internal audits / independent assessments / supply chain analysis; due diligence / conflict of interest. Tell: right-to-audit clause = contractual right to inspect the vendor; independent assessment = third-party review; supply chain analysis = evaluate the vendor's own suppliers; due diligence = investigate before signing.
- **agreements** (PRIORITY): SLA / MOA / MOU / MSA / WO-SOW / NDA / BPA. Tell: SLA = measurable service targets with penalties (numbers + penalties); MOU = non-binding statement of mutual intent; MOA = more formal agreement of roles/responsibilities (a step past MOU); MSA = master framework contract that individual SOWs hang off of; SOW/WO = the specific scope, deliverables, and timeline for one job; NDA = confidentiality only; BPA = terms of a business partnership. Drill "MOU (intent) vs SLA (metrics+penalties)" and "MSA (master) vs SOW (specific job)" hard.
- **compliance**: internal vs external reporting; consequences - fines / sanctions / reputational damage / loss of license / contractual impacts. Tell: internal reporting = to management/board; external reporting = to regulators/public; fines = monetary penalty; sanctions = restrictions/penalties imposed; loss of license = cannot operate; reputational damage = brand harm.
- **due-diligence-care** (HIGH): due diligence vs due care; attestation and acknowledgement. Tell: due diligence = doing the investigation/homework BEFORE acting (vetting a vendor); due care = the ongoing reasonable actions to protect once engaged (maintaining controls). Diligence = investigate first; care = act responsibly ongoing. Attestation = formally affirm something is true.
- **privacy**: data subject / controller vs processor / ownership / data inventory and retention / right to be forgotten. Tell: data subject = the person the data is about; right to be forgotten = the subject's right to have their data erased; data inventory = knowing what personal data you hold; retention = how long you keep it.
- **audits**: attestation; internal (compliance / audit committee / self-assessment) vs external (regulatory / examinations / assessment / independent third-party). Tell: internal audit = your own staff/committee reviews; self-assessment = the team rates itself; external audit = an outside party reviews; independent third-party = unaffiliated auditor for objectivity; attestation = a formal signed statement of compliance.
- **pentest-types** (HIGH): known / partially known / unknown environment; physical / offensive / defensive / integrated; passive vs active reconnaissance. Tell: known environment = tester has full info; partially known = some info; unknown environment = tester has no inside info; passive recon = gather info WITHOUT touching the target (OSINT, public records); active recon = directly probe/scan the target (which can be detected). Use the 701 wording, never the retired color terms.
- **awareness**: phishing campaigns / recognizing / responding; anomalous behavior (risky / unexpected / unintentional); reporting (initial / recurring). Tell: phishing campaign = simulated phishing to train users; risky behavior = knowingly dangerous; unexpected behavior = out of the norm; unintentional = accidental; initial reporting = first-time baseline; recurring reporting = ongoing cadence.
